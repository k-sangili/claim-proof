ClaimProof — MVP v0

Remote repair verification: approved scope + contractor estimate + before/after photos → Done / Not Evidenced / Out of Scope, per line item.

Working app. Run python3 server.py and this page talks to the backend: claims are saved, reports export, and — with MODEL_API_KEY set — Muse Spark / SAM 3.1 / Muse Wonder run live. Without a key it runs in local mode (rule-based + human photo review) and says so.

4. Assessor photo upload

Run a verification first, then create a link the assessor can open to upload before/after photos for that claim — no login, the link itself is the access. Share it only with the assessor, and revoke it once the photos are in. The assessor can attach photos only; they cannot change scope, estimate, or verdicts.

How the models fit (planned live path)

  • Muse Spark (muse-spark-1.3): parse scope + estimate into line items, match estimate lines to scope lines, draft the report.
  • SAM 3.1 (sam-3.1): segment the work area (e.g. “siding panels”, “trim”) in before/after photos.
  • Muse Wonder (muse-wonder-1.0): judge, from the photo pair + SAM masks, whether the work visibly happened — lighting/angle changes are why a pixel diff alone is not trusted.
  • Muse Image: deliberately not used — ClaimProof never generates evidence photos.

Verdict rule in this MVP: no scope match → Out of Scope. Scope match + photo evidence marked “Confirms” → Done. Scope match + no confirming evidence → Not Evidenced. Low-confidence items stay flagged for a human, never auto-approved.
